# 一期需求规格说明（Spec）

## 1 背景和目标

企业存在账号分散、反复登录、授权不可统管以及入调离操作重复的问题。目标是以统一身份为入口，以用户角色和角色权限关系计算业务权限，并让 HR 数据和 OA 审批结果驱动账号及授权变化。

本规格以提供的需求分析和三份市政公司表单为输入，描述当前一期实现。每条需求通过编号关联界面、接口、数据表与验收条件。版本：1.1；基线日期：2026-10-21。

## 2 角色与边界

| 角色 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 超级管理员 | 初始化平台、维护全局目录、指定部门管理员、设置委派权限上限、导入三表 | 在前端伪装为业务用户绕过真实权限判断 |
| 部门管理员 | 管理绑定部门的普通员工、维护本部门受管岗位角色、在委派范围内授权 | 指定管理员、操作其他部门员工、修改管理员、维护共享角色 |
| 普通员工 | 登录、本人改密、查看本人权限和会话、申请岗位角色、访问获授权功能 | 请求全局管理 API、自行授权、修改他人密码 |
| HR 集成端 | 发送签名入职、调岗、离职事件 | 直接修改平台管理员、凭姓名猜测员工身份 |
| OA 集成端 | 对平台已存在的申请发送签名审批结果 | 用任意回调直接创建申请或多次处理同一审批 |

平台管理员身份与权限表中“系统管理员”模板严格分开。岗位名称“经理”不构成管理授权。部门范围采用精确绑定，不自动包含子部门，避免树形变化扩大管理权限。

## 3 数据分析与映射

部门表有 111 个部门，全部上级关系可解析，形成以总公司为根的树。员工表有 10000 条，SG 用户名唯一，姓名存在重名。岗位有 54 种。分公司员工的部门用“分公司名称-部门名称”匹配部门表；总部员工使用原部门名。

权限清单包含 18 个系统、115 个模块、359 个功能。系统和模块合并单元格按前项补齐，功能和授权单元格不盲目补齐。五列角色是跨系统的业务权限模板，不是 54 个岗位的自动映射。

| 来源字段 | 目标结构 | 处理规则 |
| --- | --- | --- |
| 部门名称和上级部门 | sys_department | 名称唯一，校验缺失父节点及循环 |
| 部门经理 | manager_name 和 manager_id | 仅在所属部门唯一匹配时关联；保留未关联原文 |
| 员工用户名和姓名 | sys_user | 保留 SG 标识，导入时无密码和管理标记 |
| 分公司 部门 岗位 电话 | employee_profile 与 sys_post | 组织必须匹配；岗位角色一对一，但不自动授权 |
| 系统 模块 功能 说明 | biz_system sys_module sys_function | 按层级拆分，功能名称在模块内唯一 |
| 五类角色的操作清单 | sys_permission permission_detail permission_template | 按具体操作拆分，模板明确应用后才改变角色权限 |

发现两处英文 view，按查看规范化；一处普通员工权限为空，保留未确认且不授权。查看本人和编辑本人保留独立权限编码；平台仅管理授权，具体业务仍须检查数据归属。全部仅展开该功能已有的具体操作，不凭空生成删除权限。“无”表示不授予，不作为覆盖其他角色的拒绝规则。

保留 SG 用户名作为稳定业务标识。重复导入不更新已有授权；组织岗位变化通过调岗处理。

## 4 功能规格

每项均说明触发输入、可观察行为与验收条件；本节描述当前实现。

### AUTH-01 登录与密码策略

前置与输入：账号或唯一手机号、密码。

系统行为：认证成功返回 JWT 和身份；5 次失败锁定 5 分钟；首次重置后先改密。

验收条件：错误密码不能登录；首次改密后旧 JWT 返回 401。

### RBAC-01 角色授权与权限并集

前置与输入：管理员、用户、角色和权限编号。

系统行为：有效权限为全部启用角色权限的并集；停用应用的权限不计入。

验收条件：两角色提供同权限，回收一个仍可访问；回收全部后同 JWT 返回 403。

### SCOPE-01 部门管理范围

前置与输入：超管绑定的精确部门、委派权限。

系统行为：后端同时核对操作身份、目标员工部门、受管角色和权限上限。

验收条件：跨部门重置密码返回 403；普通用户管理 API 返回 403。

### IMPORT-01 三表校验预览与提交

前置与输入：部门、员工、功能权限三个 XLSX。

系统行为：先预览后确认；错误阻止提交；30 分钟预览仅创建者可用；单事务提交。

验收条件：111 部门、10000 员工、54 岗位、797 权限；初始员工授权 0；重复提交 reused=true。

### ORG-01 组织岗位与目录

前置与输入：部门父节点、岗位、应用模块功能。

系统行为：部门不成环；岗位对应角色；模板明确应用后追加权限；岗位字段不自动授权。

验收条件：非法父节点被拒绝；应用模板不会自动增加员工角色。

### SESSION-01 会话与撤销

前置与输入：当前 JWT 或会话编号。

系统行为：保存数据库会话；本人可撤销；管理员可强制下线；空闲 30 分钟失效。

验收条件：注销或强制下线后旧 JWT 返回 401。

### OIDC-01 本地双客户端单点登录

前置与输入：平台会话、client_id、redirect_uri、PKCE S256。

系统行为：两个本地客户端用授权码登录；校验 state、nonce、签名及受众。

验收条件：第二客户端无需再输密码；授权码二次交换返回 400。

### OA-01 申请与审批联动

前置与输入：员工申请 roleId；OA 签名回调 approvalId、decision。

系统行为：先创建 PENDING；审批锁定记录；只批准申请内的岗位角色。

验收条件：批准授予角色；拒绝不授予；同事件重试 reused=true。

### HR-01 入职调岗离职联动

前置与输入：HR 签名事件 JOIN、TRANSFER、LEAVE。

系统行为：入职无密码无授权；调岗事务替换组织和完整角色集合；离职停用撤权撤会话。

验收条件：同编号不同内容返回 409；离职旧 JWT 返回 401；HR 不自动变更管理员。

### AUDIT-01 操作记录与字典

前置与输入：操作人、事件类型；字典分类编码名称。

系统行为：记录登录及管理操作；管理范围控制查询；字典按分类编码存储。

验收条件：普通员工不能读取管理审计；分页返回 items 和 total。

### UI-01 中文交互与错误反馈

前置与输入：浏览器操作与 API 响应。

系统行为：Vue3 + TypeScript + Tailwind；必填校验；成功刷新；401 回登录、403 保持会话提示。

验收条件：真实页面截图展示导入、用户和登录失效；前端类型检查及构建成功。

## 5 核心业务规则

有效权限等于用户全部启用角色所拥有、且所属应用启用的权限并集。回收一个角色时，如果另一角色仍提供同一权限，则保留该权限。没有拒绝优先、角色继承或互斥规则。

业务端旧 JWT 通过数据库会话验证登录，再查询当前权限；回收角色后同一 JWT 返回 403，注销后返回 401。OIDC 令牌使用独立签名和协议端点；本地权限检查接口还检查会话和权限版本。离线验证只能证明签名和有效期，不能保证即时撤权，业务应用需要在线查询或与平台约定失效策略。

导入为一个提交单元。预览不改数据库；提交时再次确认预览归属、有效期、错误数量和警告确认。员工用户名如果撞到已有非导入账号，整批回滚。已有组织岗位变化必须通过调岗处理，不覆盖现有授权。

调岗事件明确给出新部门、岗位和完整角色列表，先校验，再在同一事务内回收旧角色并设置新角色。离职停用账号、回收角色、撤销会话。平台管理员不能被 HR 自动停用，必须先人工解除管理身份。

OA 审批结果必须关联已有申请。拒绝不授予角色；批准后为申请人添加申请角色。相同事件编号与相同内容重复提交返回已处理；同编号不同内容拒绝。已处理审批不能通过另一个事件编号改写结果。

## 6 功能分解与实现方法

本阶段按功能组织用例：认证、账号维护、目录配置、授权、有效权限查询、导入、审批回调和员工同步。控制器负责 HTTP 输入和身份入口，服务负责规则与事务，Repository 或参数化 SQL 负责存取。不以设计模式数量作为目标。

导入功能分为读取 XLSX、校验计划、预览、事务提交。认证分为密码验证、账号策略、会话签发与鉴权。OA/HR 共用签名和事件幂等入口，分别执行审批和员工生命周期规则。独立保存原始目录与当前授权，避免每次同步重置人工授权。
