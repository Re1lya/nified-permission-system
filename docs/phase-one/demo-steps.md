# 一期本地演示步骤

先按本目录 README 构建并启动。全程使用本机隔离 H2 和虚构表单，重新启动会清空数据。以下步骤区分平台登录、业务授权与外部系统演示。

| 顺序 | 操作 | 预期效果和讲解重点 |
| --- | --- | --- |
| 1 | 管理员打开 `/ui/index.html` 登录 | 密码验证后进入工作台。平台超级管理员与业务“系统管理员”模板不同 |
| 2 | 运行 `python scripts/make-demo-workbooks.py` | 在 output/demo-workbooks 生成 3 份虚构表单，不公开真实员工信息 |
| 3 | 三表导入页选择三个文件，点击预览 | 显示 3 部门 2 员工 2 岗位 1 系统 2 功能。预览不写库，未确认时禁止提交 |
| 4 | 勾选规则后提交，再用相同文件重试 | 第一批事务写入；第二次 reused=true，不重复创建。新员工无密码无角色 |
| 5 | 岗位页给财务专员应用适当模板，用户页明确分配岗位角色 | 分清岗位字段、实际用户角色关联、模板角色权限三层含义 |
| 6 | 为演示员工设置密码，用该账号登录并改密 | 首次密码不能用于普通业务操作；本人改密成功后旧会话失效，再登录 |
| 7 | 查看我的权限；请求报销权限演示 | 工作簿目录编码不是固定 expense:list。未另行授予报销示例权限应返回 403，不假装真实接入 |
| 8 | 按原 `scripts/demo-data.py` 验收，或在管理员界面创建 expense:list 并赋予两个角色 | 有权限 200；回收一个角色仍 200；回收所有来源后相同 JWT 403；注销旧 JWT 401 |
| 9 | 运行 `python scripts/oidc-demo.py`，门户建立 SSO 会话后打开两客户端 | 两端均验证签名和 PKCE；第二端不再输入密码。此时仅认证成功，不代表全部业务授权 |
| 10 | 配置集成密钥后运行 `scripts/verify-phase-one.py` | 用真实 HTTP 执行入职、改密、申请、OA 批准、调岗、离职及幂等验证；结果只保存检查结论 |
| 11 | 查看同步记录、登录日志和操作日志 | 展示本地 OA/HR 来源事件、审批结果和管理记录 |
| 12 | 打开四份 Word 和测试报告 | 根据需求、原型、接口、数据库解释功能分解；按 Spec 编号展示界面、Apifox 契约、ER 图、SQL 和实际测试报告 |

脚本中的 HTTP 前缀测试员工在离职验收后保留停用记录。不要为了整理演示而删除未知人员。演示结束可停止本次 Java 和两个本地客户端进程；不连接其他服务器或数据库。

可讲解的设计理由：账号与员工档案分开；多对多授权关系独立；岗位和角色映射不会隐式授权；外部事件先验签、再做幂等和事务；登录失效与业务无权用不同 HTTP 状态表示。
