# 参考 RBAC-admin 的第一轮改进

参考仓库：[Noah-hope/RBAC-admin](https://github.com/Noah-hope/RBAC-admin)。本次阅读的本地提交为 `9857e5e1aeed46c774ef0c7710473a7bb5d889eb`。借鉴其账号及会话生命周期、事务边界和接口验收思路，在现有 RBAC0 项目内实现；本项目继续使用 Java 21、Spring Boot 4、JPA 和 CloneFactory。

## 已落实

| 参考思路 | 本项目的改进 | 验收方式 |
|---|---|---|
| 每次业务调用检查当前会话和账号状态 | JWT 签名、必需字段、用户、时间与数据库会话共同校验；拒绝未登记会话 | 非法、过期、缺少字段或未登记的令牌返回 `401` |
| 账号变更要撤销会话 | 改密码、停用和删除账号同步撤销全部会话；再次启用不能复活旧令牌 | 旧令牌为 `401`，新登录正常 |
| 会话撤销应跨实例生效 | 用共享数据库保存有效会话，注销删除当前会话，移除内存黑名单 | 两个独立验证器读取同一 H2 数据库，均拒绝已注销令牌 |
| 账号与会话变更在同一事务提交 | 登录和账号命令锁定同一用户行；密码修改与会话撤销一起提交或回滚 | 事务回滚保留原会话；H2 测试覆盖登录先于重置、重置先于登录两种并发顺序 |
| 权限校验读取当前配置 | 有效权限同时过滤停用的用户、角色及业务系统；示例接口在同一 Service 事务内校验登录和权限 | 角色回收或系统停用后业务接口为 `403` |
| 从 HTTP 边界验收 | MockMvc 调用实际 Controller、Service、JPA 和独立 H2 数据库；每个请求单独提交 | 密码、账号、权限、注销及错误状态回归测试 |

会话表只存随机 `jti`、用户 ID、签发及到期时间，不保存明文 JWT 或密码。为适应当前项目，采用删除会话来撤销登录；参考项目的凭据版本、会话纪元、多受众令牌及审批模型不在本轮范围内。

本地 H2 依然是内存模式，应用重启时数据清空。使用共享、持久化 MySQL 时，会话及注销结果随数据库保留。测试中的独立验证器验证共享状态，不等于已完成真实双服务器故障、时钟和数据库隔离级别验证。

## 运行与数据库升级

首次构建先按 [clonefactory.md](clonefactory.md) 安装内置注解处理器，再执行：

```powershell
$env:JAVA_HOME = 'C:\Users\姚景云\.jdks\corretto-21.0.12.1'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn "-Dmaven.repo.local=D:\CodexData\cache\m2" clean package
```

新 MySQL 数据库使用 [database-mysql.sql](database-mysql.sql)，已有数据库使用 [migrations/20261019-login-sessions.sql](migrations/20261019-login-sessions.sql)。本次只编写脚本，未连接或修改服务器数据库。升级后所有用户重新登录，多实例应统一切换应用版本。过期会话的维护清理方式见 [deployment-two-servers.md](deployment-two-servers.md)。

手动验收顺序见 [rbac-api.md](rbac-api.md) 的“新增会话与状态验收”。自动测试不启动监听端口。

## 建议继续的顺序

1. **管理 API 鉴权和管理范围。** 当前用户、角色、权限配置接口仍是演示接口，需要设计首次管理员初始化、管理员角色和部门管理范围，再统一接入后端校验。
2. **审计与幂等。** 记录谁修改了哪个账号或授权、修改原因和结果；OA 重试相同操作时避免重复授权。授权变更与审计应使用同一事务。
3. **数据库版本管理及 MySQL 验证。** 引入 Flyway 等工具管理升级，补真实 MySQL 并发登录、密码重置和多实例注销测试。
4. **对照实际需求补业务。** 确认部门、员工和权限 Excel 字段，再做导入、部门管理员与 OA 审批；增加与当前 API 联调的管理页面。

参考仓库中已实现与规划中的功能需分开判断。其前端原型也不能直接视为已经联调的管理端；本项目的需求、完成情况和交付验收继续以自身实现为准。
